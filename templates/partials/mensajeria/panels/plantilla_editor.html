{% comment %} The Crear plantilla editor -- the screen behind the chooser's "Empezar a crear" card, swapped into #mensajeria-panel (or served inside the full page shell for plain navigation). A two-column grid: the form card on the left, the sticky live preview (partials/plantillas/whatsapp_preview.html) on the right. The form hx-posts back to plantilla_editor: success answers with the Plantillas panel (back to the list), errors re-render this template with inline role="alert" messages wired to their inputs via aria-describedby (shell.js then focuses the first invalid field). Radio groups are fieldsets so the section headings double as programmatic group names. All live behavior -- name lowercasing/validation, the category-dependent sub-type groups, header/button panels, counters, variable insertion, sample inputs and the preview -- is delegated in static/js/shell.js off the data-* hooks; core.plantillas re-validates everything server-side. Autenticación is the one category that does not use the copy fields at all: WhatsApp writes and localizes an OTP message itself and refuses one that arrives with its own body, so picking that card swaps Cabecera / Cuerpo / Pie / Botones for the three settings it does accept ([data-auth-panel]). Both blocks stay in the DOM and toggle on `hidden`; core.plantillas ignores whichever one the category did not ask for.
